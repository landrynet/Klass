# PARTIE N — SCRIPT DE RÉINITIALISATION DES DONNÉES DE TEST

Le script doit être clairement documenté.

Exemple d'utilisation :

```bash
python manage.py reset_test_data
```

ou utiliser l'architecture de commande existante du projet si elle est différente.

Le script doit :

1. supprimer proprement les données de test ;
2. préserver la structure de la base ;
3. préserver les migrations ;
4. recréer une école de test complète ;
5. recréer les données nécessaires à tous les modules.

IMPORTANT :

Ne pas supprimer les données de production par erreur.

Le script doit être explicitement réservé au développement/test.

Si nécessaire, demander une confirmation ou vérifier l'environnement avant l'exécution.

# PARTIE U — VÉRIFICATION GIT ET PUSH GITHUB OBLIGATOIRE

Après avoir terminé :

* la refonte ;
* les corrections ;
* les tests ;
* la documentation ;
* la mise à jour du README.md ;
* le script de réinitialisation ;
* la création des données de test ;

exécuter :

```bash
git status
```

Puis :

```bash
git diff
```

Vérifier que toutes les modifications nécessaires sont présentes.

Ensuite :

```bash
git add .
```

Créer un commit clair :

```bash
git commit -m "Complete Phase 3.5 - UI redesign and system stabilization"
```

Puis pousser obligatoirement :

```bash
git push origin main
```

Vérifier ensuite :

```bash
git status
```

Le dépôt doit être synchronisé avec GitHub.

Résultat attendu :

```text
Your branch is up to date with 'origin/main'
working tree clean
```

Si le push échoue :

1. identifier la cause ;
2. corriger le problème ;
3. réessayer ;
4. vérifier à nouveau le dépôt.

Ne pas déclarer la phase terminée tant que le push GitHub n'est pas réussi.
