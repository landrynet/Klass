# PARTIE A — AJUSTEMENT FINAL DE LA PHASE 1

## 1. INFORMATIONS D'ACCÈS APRÈS LA CRÉATION D'UNE ÉCOLE

Actuellement, lorsque le Super Admin crée une école, l'Admin École est créé automatiquement, mais les informations nécessaires pour permettre à cet Admin École de se connecter ne sont pas correctement affichées au Super Admin.

Corriger ce flux.

Après la création réussie d'une école, le Super Admin doit recevoir une confirmation claire contenant les informations nécessaires pour transmettre l'accès à l'Admin École.

Le flux attendu est :

```text
Super Admin
    ↓
Crée l'école
    ↓
L'école est créée
    ↓
Le tenant est créé
    ↓
Le domaine est créé
    ↓
L'Admin École est créé
    ↓
Les informations d'accès temporaires sont générées
    ↓
Page de confirmation
    ↓
Le Super Admin peut transmettre les informations à l'Admin École
```

La page de confirmation doit afficher clairement :

* le nom de l'école ;
* l'identifiant ou email de connexion de l'Admin École ;
* le lien personnalisé de connexion ;
* le lien d'accès approprié ;
* les informations nécessaires à la première connexion.

Le Super Admin doit pouvoir facilement :

* copier l'identifiant ;
* copier le lien ;
* copier les informations nécessaires à transmettre ;
* utiliser une action de copie claire et pratique.

---

## 2. GESTION DU MOT DE PASSE TEMPORAIRE

Le mot de passe temporaire doit être géré de manière sécurisée.

Le système doit permettre au Super Admin de transmettre les informations nécessaires à l'Admin École lors de la création.

Cependant :

* ne pas exposer inutilement le mot de passe après cette étape ;
* ne pas afficher le mot de passe dans la liste des écoles ;
* ne pas afficher le mot de passe dans le profil de l'école ;
* ne pas stocker le mot de passe en clair ;
* ne jamais permettre au Super Admin de consulter ultérieurement le mot de passe.

Si l'architecture de sécurité existante ne permet pas d'afficher le mot de passe temporaire de manière appropriée, mettre en place un mécanisme sécurisé adapté, par exemple :

* affichage unique après création ;
* téléchargement sécurisé des informations d'accès ;
* copie immédiate ;
* ou mécanisme équivalent conforme aux règles de sécurité.

L'objectif est simple :

> Le Super Admin doit pouvoir transmettre l'accès initial à l'Admin École, sans que le système expose ensuite le mot de passe.

La Phase 1 possède déjà une logique de création de l'année scolaire initiale dans l'assistant de configuration.

La Phase 2.0 ne doit donc pas créer un deuxième système indépendant.

Avant toute modification :

1. Identifier le modèle existant utilisé pour l'année scolaire.
2. Identifier la logique de création existante.
3. Identifier les relations avec l'école, le tenant et la configuration initiale.
4. Réutiliser cette architecture.
5. Étendre proprement la fonctionnalité.
6. Préserver totalement la compatibilité avec la Phase 1.

Ne jamais créer de modèle concurrent ou de deuxième logique pour les années scolaires sans nécessité absolue.

La Phase 2.0 doit être une extension cohérente de la Phase 1.
